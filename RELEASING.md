# Releasing AnyFile

Publishing a GitHub release with a tag like `v1.0.0` runs
`.github/workflows/release.yml`. The tag sets the version
(`.github/scripts/stamp-version.sh` writes it into `giode.toml`), and the run
number sets the build number, so every App Store upload gets a new one. The
workflow tests the engines, builds every package and attaches the downloads to
the release. It can also be run by hand (Actions → Release → Run workflow) for
an existing tag.

The workflow is hand-written, not generated by `giode ci`: it adds the
`anyprobe` command-line tool next to the app, builds one universal macOS app
and renames the MSIX for the Store. Don't run `giode ci -f` here. It pins the
Giode CLI (`GIODE_CLI`, now `v0.1.35-alpha.1`) and takes Go from `go.mod`;
update both deliberately.

| Where | What the release gets | Needs |
| --- | --- | --- |
| GitHub, Windows | `setup.exe` installers and portable `.zip`s, x64 and ARM64 | nothing |
| GitHub, macOS | a universal `.dmg` and `.zip` | a Developer ID certificate, or macOS refuses to open it once downloaded |
| GitHub, Linux | `.deb`, `.rpm` and `.tar.gz`, x64 and ARM64 | nothing |
| Microsoft Store | `.msix` for x64 and ARM64, in the run's `store-windows-*` artifacts | a Partner Center account and the reserved name |
| Mac App Store | a `.pkg`, in the run's `store-macos` artifact | an Apple Developer account and the store certificates and profile |

The store packages are kept as workflow artifacts (download them from the run's
summary page), not attached to the release: they aren't for end users.

## Repository secrets

Set these in GitHub under Settings → Secrets and variables → Actions. Each
`*_BASE64` secret is the file encoded with `base64 -i file | pbcopy` on macOS,
or `base64 -w0 file` on Linux. Without a secret, that step is skipped and the
rest of the release still builds.

| Secret | What it is |
| --- | --- |
| `MACOS_CERT_BASE64`, `MACOS_CERT_PASS` | The "Developer ID Application" certificate as a `.p12`, and its password: signs the app and the `.dmg` |
| `GIODE_NOTARY_ID`, `GIODE_NOTARY_TEAM_ID`, `GIODE_NOTARY_PASS` | Your Apple ID, team ID and an app-specific password: notarizes the `.zip` and `.dmg` |
| `MACOS_STORE_CERT_BASE64`, `MACOS_STORE_CERT_PASS` | The "Apple Distribution" certificate as a `.p12` |
| `MACOS_INSTALLER_CERT_BASE64`, `MACOS_INSTALLER_CERT_PASS` | The "Mac Installer Distribution" certificate as a `.p12` |
| `MACOS_PROFILE_BASE64` | The Mac App Store provisioning profile (`.provisionprofile`); never commit it |

The Mac App Store build runs only when the last three are all set.

## Mac App Store

1. Join the Apple Developer Program.
2. In Certificates, Identifiers & Profiles:
   - Register the App ID `com.xmhrnx.anyfile` (the `app.id` in `giode.toml`).
   - Create an "Apple Distribution" and a "Mac Installer Distribution" certificate.
   - Create a "Mac App Store" provisioning profile for the App ID.
3. In App Store Connect, create a macOS app with the same bundle ID.
4. Add the Mac App Store secrets above, then publish a release. Download
   `AnyFile-<tag>-macos-appstore.pkg` from the run's `store-macos` artifact and
   upload it with the Transporter app.
5. Fill in the listing (copy below):
   - **App Privacy:** "Data Not Collected".
   - **Category:** Utilities (already set in the build).
   - **Export compliance:** answered in the build
     (`ITSAppUsesNonExemptEncryption = false`).
   - **Age rating:** no objectionable content in any category: 4+.
   - **Privacy Policy URL:** https://xmhrnx.github.io/anyfile/#privacy

**The App Sandbox limits AnyFile in the store version**, and the app already
behaves accordingly (`platform.Sandboxed()`):

- **Built-in engines only.** The sandbox can't run the user's TrID, Magika,
  7-Zip or FFmpeg, and the store allows no downloaded programs, so Settings
  hides the engine installer and the tool paths. 7z/rar/cab/dmg and media
  streams aren't explored; everything in the built-in engines is.
- **No `anyprobe`.** The command-line tool is only in the GitHub download.
- **Files:** AnyFile reaches only files the user opens, drops or sends to it,
  and folders they pick to extract into.
- **No update check or Ko-fi link:** the store updates the app, and Apple
  doesn't allow outside payment links.

The notarized `.dmg` on GitHub has none of these limits.

## Microsoft Store

1. In Partner Center (the same account as EasySend), reserve the name
   "AnyFile File Inspector", the name the MSIX is built under.
2. The Product identity page's values are already in `giode.toml` under
   `[windows.msix]`: `identity_name = "MehranZahir.AnyFileFileInspector"`,
   `publisher = "CN=B40E8F57-A7E0-40BB-8E74-5D051D0B578B"`,
   `publisher_display_name = "Mehran Zahiroddini"`. Check they still match.
3. Publish a release. The workflow sets the display name to the reserved name
   for the MSIX build only. Download `AnyFile-<tag>-amd64.msix` and
   `AnyFile-<tag>-arm64.msix` from the `store-windows-*` artifacts and upload
   both in one submission. The Store signs them.
4. AnyFile is a full-trust desktop app: when the submission asks why it uses
   `runFullTrust`, say it inspects any file the user opens, extracts to folders
   they choose, hands items to their default apps, and adds "Inspect with
   AnyFile" to Explorer's menu. The MSIX doesn't check GitHub for updates (the
   Store updates it); otherwise it is the same app as the GitHub download.
5. **Privacy policy URL:** https://xmhrnx.github.io/anyfile/#privacy. Age
   rating questionnaire: no content of concern, no user interaction, no data
   sharing, no purchases.

## Store listing

**Name:** AnyFile (Microsoft Store: AnyFile File Inspector)

**Subtitle / short description (≤ 80 characters):**
Find out what any file really is, then explore and open what's inside.

**Keywords (Apple, ≤ 100 characters):**
file type,identify,inspector,extract,archive,zip,pdf,attachments,forensics,hex,unknown file

**Description:**

> AnyFile tells you what any file really is, whatever its name says, lets you
> explore everything inside it, and opens each part in the app your system
> already uses for that type.
>
> Identify: built-in signatures and structural probes recognize the real type
> of a file with a wrong or missing extension, with text, encoding and entropy
> analysis when nothing else is sure.
>
> Explore: open containers inside containers, a zip inside an email, the
> spreadsheet inside that zip, the image inside that spreadsheet. AnyFile
> reads ZIP-based formats (Office documents, jar, apk, epub), tar and
> compressed streams, Office compound files, msi and msg, PE, ELF and Mach-O
> executables, PDF attachments, images and fonts, email and mailboxes, ISO disc
> images and encoded data inside text, and a deep scan finds files embedded
> anywhere.
>
> Open: every part opens in your own viewer for its detected type, or save it,
> or extract a whole container with its folders. AnyFile never renders content
> itself.
>
> Everything happens on your computer. No accounts, no ads, no tracking.

Add for the Microsoft Store: "Optional engines (TrID, Magika, 7-Zip, FFmpeg)
can be installed from Settings." Leave that out for the Mac App Store.

**Category:** Utilities (Mac App Store), Utilities & tools (Microsoft Store).

**Screenshots:** `site/img/welcome.png`, `mismatch.png`, `nested.png`,
`office.png`, `no-extension.png`: 1440 × 900, which both stores accept for
desktop apps.

## Linux

The `.deb`, `.rpm` and `.tar.gz` are attached to the release, and the website's
download section links to them. There is no Snap Store or Flathub package.
